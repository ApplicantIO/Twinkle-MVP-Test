# Style Guide

## Code Style

- Prefer clear, self-explanatory naming
- Keep functions focused and composable
- Add comments only for non-obvious logic

## Change Style

- Use surgical diffs over broad rewrites
- Keep behavior backward-compatible unless explicitly changing behavior
- Reuse existing UI and utility patterns in the codebase

## Validation

- Run targeted checks for touched areas
- Resolve introduced lint issues before finalizing changes
